# crosspad-apps — notes for contributors and agents

The CrossPad app registry, CP Tools (the shared app manager) and the one-line
installer. User documentation is on the docs site, https://crosspad.app/docs/
(setup: [Start here](https://crosspad.app/docs/start-here/); apps:
[install](https://crosspad.app/docs/how-to/install-apps/),
[new app](https://crosspad.app/docs/how-to/new-app/),
[publish](https://crosspad.app/docs/how-to/publish-app/); commands:
[reference/cli](https://crosspad.app/docs/reference/cli/)). Link there instead
of repeating setup steps in this repo.

## Layout

| Path | What | Notes |
|---|---|---|
| `registry.json` | The catalog | Generated by `build_registry.py`; never edit by hand |
| `README.md` | Repo landing page + registry contract | Three blocks between `<!-- …_START -->` / `<!-- …_END -->` markers are rewritten by `build_registry.py` |
| `COMMUNITY_APPS.md` | Full community list | Generated by `build_registry.py` |
| `external-apps.json` | Non-org app repos | Changed by PR; a push to `main` rebuilds the registry |
| `build_registry.py`, `diff_registry.py` | CI | `.github/workflows/build-registry.yml` |
| `crosspad_app_manager.py` | CP Tools core (CLI + TUI) | Downloaded by every platform wrapper |
| `template/` | App template for `new` / `idf.py app-new` | Fetched as the repo tarball by projects that have no local copy |
| `install/` | `install.sh`, `install.ps1`, illustrated `README.md` | Benches: `install/test/README.md` |
| `docs/app-manager.md` | CP Tools details the site does not cover yet | User-facing; linked from `README.md` |
| `tests/` | pytest suite for the core and the template | |

## Automation

- `build-registry.yml` runs every 6 h, on `repository_dispatch: app-released`,
  on a push to `main` touching `build_registry.py` or `external-apps.json`, and
  by `workflow_dispatch`. It commits `registry.json`, `README.md` and
  `COMMUNITY_APPS.md` as `chore: update registry.json [automated]`. Private org
  app repos are read with the `ORG_READ_TOKEN` secret (falls back to
  `GITHUB_TOKEN`).
- Keep all three marker pairs in `README.md` (`LATEST_UPDATES`, `APP_TABLE`,
  `COMMUNITY_TOP`). `update_readme()` skips a block whose START marker is
  missing, but fails if a START has no END.
- `diff_registry.py` only writes workflow outputs; nothing posts them anywhere.

## CP Tools core

- Platform wrappers (`tools/app_manager.py` in platform-idf,
  `scripts/app_manager.py` in crosspad-pc and the Arduino firmware) download
  `crosspad_app_manager.py` from raw `main` and refresh it hourly, so a merge to
  `main` reaches users within the hour. platform-idf CI pins it to a commit
  instead (`CROSSPAD_APPS_CORE_REF`, from `tools/app_manager.core-ref`).
- It must load through `importlib.util.spec_from_file_location` (the way the
  wrappers load it) and run on Python 3.10.
- The registry, the template and the core itself are fetched over anonymous
  HTTPS; `gh` is only a fallback and is needed only to publish.

## Tests

```bash
python -m pip install pytest
python -m pytest tests -q
bash -n install/install.sh
```

CI (`test.yml`) runs them on Linux, Windows and macOS with Python 3.10 and 3.13,
and parses `install.ps1` under Windows PowerShell 5.1 and 7. The full
installer benches (Docker Ubuntu, Windows 11 VM) are in
[`install/test/README.md`](install/test/README.md).

## Docs

The docs site quotes facts from this repo: the installer one-liners and default
folders, the ESP-IDF version the installer pins (`install.sh` / `install.ps1`),
Python 3.10, the `cptools` / `crosspad-*` shims, the registry URL, the
`crosspad-app` topic, `external-apps.json`, the app count, and the path
`install/README.md` (linked from the site). It also generates its app catalog
page from `registry.json`.

A change that breaks a docs page (command, output, path) opens an issue in CrossPad/crosspad-docs.

A change to behaviour described in `docs/app-manager.md` or `install/README.md`
updates that file in the same PR.
